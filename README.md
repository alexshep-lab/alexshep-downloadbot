# AlexShepDownloadBot

Telegram-бот, который скачивает видео из YouTube (включая Shorts), Instagram (Reels, посты),
TikTok и X (бывший Twitter) и присылает их в чат. Работает на [aiogram 3](https://docs.aiogram.dev/) + [yt-dlp](https://github.com/yt-dlp/yt-dlp).

## Требования

- Python 3.11+ (проверено на 3.14)
- [ffmpeg](https://www.gyan.dev/ffmpeg/builds/) в PATH — нужен yt-dlp для склейки видео и звука
  (`winget install ffmpeg`)

## Установка

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

## Настройка

1. Создай бота у [@BotFather](https://t.me/BotFather) (`/newbot`) и получи токен.
2. Скопируй `.env.example` в `.env` и впиши токен в `BOT_TOKEN`.
3. Обязательно впиши свой Telegram id в `ALLOWED_USER_IDS`. Если оба списка доступа
   пусты, бот не запустится. Свой id подскажет [@userinfobot](https://t.me/userinfobot).

## Запуск

```powershell
.venv\Scripts\python bot.py
```

или просто двойной клик по `run_bot.bat`.

Дальше — пришли боту ссылку на видео, он ответит файлом.

## Доступ по одобрению автора

Владельцы бота — `ALLOWED_USER_IDS`: им можно всё, и они решают, кого пускать.

- Бота добавили в группу → он просит участников написать автору (`OWNER_USERNAME`)
  в личку и попросить доступ, а владельцу параллельно приходит запрос: название, id, ссылка или
  «закрытая», число участников, кто добавил — и кнопки «✅ Разрешить / ❌ Отказать».
  Если бота добавил сам владелец, группа разрешается сразу.
- Незнакомый человек пишет в личку → бот просит его написать автору, а владельцу
  приходит такой же запрос с именем, @ником и id.
- После решения бот сообщает его группе или человеку. Передумать можно кнопкой под
  запросом или командой `/access` (в личке): список всех групп и людей с кнопками.
- Разрешение группы действует для всех её участников, включая анонимных админов.
- Решения хранятся в `access.json` рядом с кешем. `ALLOWED_CHAT_IDS` — стартовые
  разрешения для групп без записи; их тоже можно отозвать через `/access`.

## Использование в группе

1. У [@BotFather](https://t.me/BotFather): `/mybots` → выбери бота → **Bot Settings** →
   **Group Privacy** → **Turn off**. Иначе бот не видит обычные сообщения в группах.
   Если бот уже был в группе — удали его из группы и добавь заново, только после
   этого настройка применится.
2. Добавь бота в группу и отправь там команду `/id` — бот покажет id чата
   (отрицательное число).
3. Впиши этот id в `ALLOWED_CHAT_IDS` в `.env` и перезапусти бота.

После этого бот будет скачивать видео по любой ссылке YouTube/Instagram,
появившейся в группе, а на остальные сообщения реагировать не будет.

Учитывай: доступ получает каждый участник разрешённой группы. Если подключены cookies,
участники смогут скачивать всё, что видит аккаунт из этого файла. Используй отдельный
аккаунт без личной переписки и не добавляй недоверенные группы.

## Cookies (если Instagram или YouTube требуют вход)

Instagram часто отдаёт видео только залогиненным, а YouTube на серверных IP пишет
«Sign in to confirm you're not a bot». Лечится файлом cookies:

1. Поставь в браузер расширение **Get cookies.txt LOCALLY** (Chrome/Firefox).
2. Залогинься на сайте (для Instagram лучше завести **отдельный** аккаунт —
   основной может словить ограничения за автоматизацию).
3. Экспортируй cookies в файл `cookies.txt` в папку бота.
4. В `.env` укажи `COOKIES_FILE=cookies.txt` и перезапусти бота.

Альтернатива одной командой (возьмёт cookies из установленного Chrome):

```powershell
.venv\Scripts\yt-dlp --cookies-from-browser chrome --cookies cookies.txt --skip-download https://www.instagram.com/
```

## YouTube: PO-токен вместо cookies

Без PO-токена YouTube отдаёт анонимному yt-dlp только клиент, у которого загрузка
обрывается с HTTP 403, а с cookies аккаунта включает SABR-режим и оставляет лишь 360p.
Лечится провайдером PO-токенов [bgutil-ytdlp-pot-provider](https://github.com/Brainicism/bgutil-ytdlp-pot-provider):
плагин ставится из `requirements.txt`, а сам генератор токенов — отдельным контейнером:

```bash
docker run --name bgutil-provider -d --init --restart unless-stopped -p 127.0.0.1:4416:4416 brainicism/bgutil-ytdlp-pot-provider:2.0.0
```

yt-dlp находит его на `http://127.0.0.1:4416` сам. Версия контейнера должна совпадать с версией плагина.

## Воспроизведение на iPhone

Telegram на iPhone не играет VP9, AV1 и 10-битный H.264, а без индекса в начале файла
не может стримить видео. Поэтому бот выбирает H.264, а если сайт отдал другое — после
скачивания проверяет файл через ffprobe и приводит его к H.264 8 бит + AAC с `+faststart`
(видео длиннее `TRANSCODE_MAX_DURATION_MIN` уходят как есть: на слабом сервере кодирование
идёт примерно в реальном времени). Качество ограничивается по короткой стороне кадра,
поэтому вертикальные Shorts и рилсы качаются в 1080×1920, а не в 480×854.

## Лимиты и как их обойти

- **50 МБ на файл** — лимит Telegram Bot API. Бот автоматически понижает качество
  (1080p → 720p → 480p → 360p), пока видео не влезет. Если не влезло даже в 360p —
  скажет об этом. Обход лимита до 2 ГБ — свой [локальный Bot API server](https://github.com/tdlib/telegram-bot-api)
  (можно добавить позже).
- **yt-dlp надо обновлять**: YouTube и Instagram регулярно меняют защиту.
  Если скачивание сломалось, первым делом:

  ```powershell
  .venv\Scripts\python -m pip install -U yt-dlp
  ```

## Настройки в .env

| Переменная | Описание |
|---|---|
| `BOT_TOKEN` | токен от @BotFather (обязательно) |
| `ALLOWED_USER_IDS` | кто может пользоваться ботом, id через запятую; оба списка не могут быть пустыми |
| `ALLOWED_CHAT_IDS` | разрешённые группы (id отрицательный, узнать — /id в чате) |
| `COOKIES_FILE` | путь к cookies.txt для Instagram/YouTube |
| `COOKIES_SERVICES` | кому подставлять cookies: `ig,yt,tt,x` или `all` (по умолчанию `ig`); Instagram всегда сначала пробуется анонимно |
| `COOKIES_FALLBACK_SERVICES` | кому подставлять cookies только после ошибки «нужен вход» (по умолчанию `yt`) |
| `PROXY` | прокси для скачивания (`http://...`, `socks5://...`) |
| `DOWNLOAD_DIR` | папка для временных файлов |
| `DOWNLOAD_TIMEOUT` | таймаут скачивания, сек (по умолчанию 900) |
| `UPLOAD_TIMEOUT` | таймаут отправки файла в Telegram, сек (по умолчанию 600) |
| `TELEGRAM_API_URL` | адрес локального Bot API server; пусто = облачный Telegram |
| `MAX_FILE_SIZE_MB` | лимит размера файла (50 облачный / до 2000 локальный) |
| `MAX_HEIGHT` | максимальное качество для коротких видео (1080) |
| `PREFERRED_HEIGHT` | качество для длинных и тяжёлых видео (720) |
| `HD_MAX_SIZE_MB` / `HD_MAX_DURATION_MIN` | пороги «тяжёлого»/«длинного» видео (100 МБ / 20 мин) |
| `PROGRESS_INTERVAL` | как часто обновлять статус скачивания, сек (5) |
| `CACHE_FILE` | где хранить file_id уже отправленных видео (`file_ids.json`) |
| `THROTTLE_FLOOR_KB` | порог «соединение придушили», КБ/с — ниже него берётся свежая ссылка (500) |
| `RATE_LIMIT_COOLDOWN_MIN` | пауза после HTTP 429, минут (30) |
| `MAX_CONCURRENT_DOWNLOADS` | сколько видео качать одновременно (по умолчанию 2) |
| `MAX_PENDING_REQUESTS` | общий предел выполняющихся и ожидающих запросов (12) |
| `MAX_REQUESTS_PER_USER` | предел запросов одного пользователя (3) |
| `MAX_CACHE_ENTRIES` | максимальное число записей в кеше Telegram file_id (5000) |
| `ERROR_TTL_SEC` | через сколько секунд в группах удалять сообщение об ошибке (60, 0 = не удалять) |
| `TRANSCODE_MAX_DURATION_MIN` | перекодировать для iPhone видео не длиннее стольких минут (5) |
| `IG_SESSION_CHECK_MIN` | как часто проверять, жива ли сессия Instagram в cookies, минут (60) |

## Сессия Instagram

Instagram всегда сначала скачивается без cookies, в том числе при `COOKIES_SERVICES=ig/all`.
Вход используется как запасной вариант при ошибке, указывающей на необходимость авторизации,
и для фото с музыкой. Запросы с аккаунтом выполняются по одному. При HTTP 429 действует
общая пауза сервиса; немедленного повтора с аккаунтом нет.

При подтверждённом `checkpoint_required` или `challenge_required` сессия отключается.
Публичные ролики по-прежнему пробуются анонимно, кеш продолжает работать. Блокировка хранится
в `instagram_session_state.json` рядом с кешем и сохраняется после рестарта. В файле только
SHA-256 идентификатор сессии, не cookies. Обычная ошибка HTTP 400 не считается доказательством
блокировки: дополнительная проверка выполняется только после отказа запроса с аккаунтом.

После восстановления входа экспортируйте свежие cookies с новым `sessionid`. Бот обнаруживает
новую сессию без перезапуска. Перезапись того же файла с той же сессией блокировку не снимает.
Подтверждение в приложении само по себе не гарантирует восстановления серверной сессии.
Уведомление об успешном восстановлении отправляется только после успешной загрузки с аккаунтом;
анонимная загрузка не считается проверкой cookies. Периодическая проверка читает локальный файл
и не отправляет запросов в Instagram. Для загрузок Instagram используется копия cookiejar в памяти,
поэтому ответы сервиса не перезаписывают исходный экспорт.

Для входа через IP сервера можно использовать SSH-туннель (это не гарантирует снятия ограничений):

```bash
ssh -D 1080 -N downloadbot-vps
```

и браузер с прокси `socks5://127.0.0.1:1080` (например, отдельный профиль Chrome с
`--proxy-server="socks5://127.0.0.1:1080"`), затем выгрузите cookies instagram.com оттуда.

## Фото с музыкой

yt-dlp не качает посты из фото с музыкой («No video formats found»). Бот в этом случае
берёт пост из API Instagram (нужны живые cookies) и собирает видео: одно фото — на весь
фрагмент трека, карусель — по 3–6 секунд на слайд, видео-слайды вклеиваются как есть,
музыка — тот же фрагмент, что звучит в Instagram. «🎵 Только звук» отдаёт этот фрагмент в mp3.

Выгружайте cookies **только сайта instagram.com**: выгрузка всего браузера содержит
сессии почты, банков и прочего.

## Ограничение по частоте (HTTP 429)

Instagram считает запросы без cookies анонимными и держит для них жёсткий суточный лимит.
Когда он исчерпан, приходит `HTTP 429: Too Many Requests`.

Бот в этом случае **перестаёт обращаться к сервису на `RATE_LIMIT_COOLDOWN_MIN` минут**
и отвечает, сколько осталось ждать: повторные попытки во время блокировки только
продлевают её. Пауза действует отдельно для Instagram и YouTube, а видео из кеша
продолжают отправляться как обычно.

Durable-решение — cookies (см. раздел выше): у залогиненного аккаунта лимиты
несравнимо выше. Для этого лучше завести отдельный аккаунт, не основной.

## Кнопки под сообщением

Пока идёт закачка, под статусом есть две кнопки:

- **🎵 Только звук** — бросить видео и забрать одну звуковую дорожку (mp3 192 kbps
  с названием, исполнителем и обложкой);
- **❌ Отменить** — прекратить закачку.

Нажимать может тот, кто прислал ссылку, и владелец бота (те, кто указан
в `ALLOWED_USER_IDS`). Остальным бот отвечает, что кнопка не для них.

## Повторные ссылки

Одно видео скачивается только один раз:

- если ссылку прислали второй раз (в том числе в другом чате) — Telegram пересылает
  уже загруженный файл по `file_id`, мгновенно и без скачивания (вместе с названием);
- видео и звук одного ролика кешируются раздельно;
- если то же видео прислали, пока оно ещё качается — второй запрос ждёт на замке
  и получает результат первого, а не запускает параллельную загрузку
  (две параллельные загрузки одного видео YouTube жёстко душит).

Ссылки сравниваются по id видео, поэтому `?list=…`, `?si=…`, `&t=…` дублей не создают.
Кеш переживает перезапуск бота — лежит в `file_ids.json`.
